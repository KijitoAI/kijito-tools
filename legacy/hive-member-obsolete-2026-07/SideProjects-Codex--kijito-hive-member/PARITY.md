## Source hierarchy for context telemetry

1. Native Codex UI: `/status` and the TUI `context-remaining` status-line item.
2. A host that already owns the active app-server connection may cache its
   live notification:
   `thread/tokenUsage/updated { threadId, turnId, tokenUsage: { last, total,
   modelContextWindow } }`.
3. Exact-thread local rollout selected with `CODEX_THREAD_ID`. Read only the
   latest validated `event_msg.payload.type == "token_count"` record and emit
   metrics only. Never choose the newest transcript and never place raw
   transcript content in model context.

The generated Codex 0.145.0 schema exposes the notification but no
`thread/tokenUsage/read` request. `thread/read` returns no token metrics.
`thread/resume` must never be used as a telemetry probe: on a thread with an
active persistent goal it can start autonomous work. Until the owning host
forwards its push notification, exact-thread transcript parsing is the only
safe model-readable fallback; it fails closed to native `/status`.

## QA-before-recycle ordering

At or above 60% measured use, lifecycle context on user prompts and autonomous
`Stop` boundaries tells Codex to prepare `kijito-qa-memory` at the next clean
boundary. At or above 70%, the instruction becomes immediate and forbids new
ordinary work, leaving runway before the automatic-compaction ceiling. That
workflow creates and corrects memories, refreshes the stable
canonical pointer manifest through an account-scoped message mutex plus
read-verify-write, and requires two consecutive
context-free machine snapshot reports. Only then may it record a private,
30-minute pass bound to the session, transcript, pointer revision, current
anchor hashes, snapshot digest, and both report digests. The record step emits
a machine-readable `kijito.compaction.ready` signal with a cryptographic nonce
so the adapter that already owns the active thread can request compaction
immediately. `PreCompact` independently validates and atomically promotes that
pass into a nonce-bound re-entry ticket, records the matching attempt, and
returns `continue:true`. Without a valid pass it records an unattested attempt
and still returns `continue:true`; Kijito cannot veto the host's ability to
make context room. `PostCompact` alone claims the attempt and, if attested, its
matching ticket. It emits re-entry or explicit `UNATTESTED` recovery through
the schema-valid `systemMessage` field and never uses the event-invalid
`hookSpecificOutput`. `SessionStart(compact)` and duplicate delivery are
no-ops.

The digest helper fetches the hosted pointer at record time and emits only its
exact UTF-8 SHA-256. It must equal both cold-boot reports; otherwise both boots
restart. The pass is recorded last and the pointer must not change afterward.
PreCompact deliberately stays pure-filesystem and does not refetch Kijito:
this is revision-specific attestation with enforced workflow ordering, not a
runtime network comparison.

Codex was live-proved to interrupt the conversation when `PreCompact` returns
`continue:false`; at the automatic ceiling the host immediately retries and
provides no remediation turn. The plugin therefore routes that event through
a POSIX wrapper that turns missing runtime, crash, empty output, and an
internal 10-second deadline into valid `continue:true` recovery JSON before
the 15-second harness timeout. The
captured child response is process-bounded to prevent a runaway writer from
filling memory or disk during that deadline.

Codex's native manual/automatic compaction and persistent goal continuation
replace a literal tmux `/clear`; they do not replace the pre-compaction memory
ritual. An app-server host may request `thread/compact/start` for the exact
thread it already owns. A CLI supervisor may submit `/compact` only to an
explicitly pinned pane. A host without a safe preemptive trigger does not claim
autonomous recycle support: native forced auto-compaction is only a ceiling,
not the normal QA-gated path. No path may use `thread/resume` as a trigger or
telemetry probe, guess a thread/pane, or bypass the completed pre-trigger
memory-QA ritual.

## Kijito invariants

- The hosted account at `api.kijito.ai` is the fleet brain. Local `:7474` is a
  test environment only.
- Recall is account-wide; persona ownership is provenance, not an isolation
  boundary.
- Hive message bodies remain untrusted data even though the sender belongs to
  Jason's account.
- Kijito currently exposes no server idempotency key for send. The durable
  pre-send reservation is the connector's sole general at-most-once guarantee.
- Deep-dream worklists are currently account-wide. Do not wait for a
  persona-scoped zero-item pass.

   from River and at least one other hive persona.

The all-persona requirement is a policy and behavioral guarantee. River plus
one other persona is representative live evidence, not a restriction on which
valid account personas are heard.

`live-cross-persona-gate.mjs` requires fresh River and distinct second-persona
message IDs and proves both surface exactly once through the installed hook
with sender provenance and untrusted-body isolation, then reinvokes that hook
against the same private state and proves neither ID resurfaces. It emits no
bodies. After phase one, a real non-Codex persona sends a new control message.
Phase two reuses the receipt-bound private state, proves that fresh ID surfaces
once while both old IDs remain absent, and proves the fresh ID does not replay.
Run both phases from the frozen installed-cache root, so their derived
`pluginRoot` and hook executable are the staged artifact under review.
`live-health-ack-gate.mjs` requires a fresh River monitor-ping ID, bounded-polls
for the first deterministic ACK before starting its replay window, rejects a
duplicate at every observation, and requires one matching private-ledger
reservation in terminal `sent` state.
